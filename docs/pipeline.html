Design choices that produced those numbers

  • Verifier is deterministic code: invented ids, unretrieved citations and model-written verses cannot pass (adversarial tests).
  • Scope remarks ("not exhaustive", "ask a scholar") are code-owned notes, so the model is never asked for an uncitable sentence.
  • Retry shows the model its rejected answer and a fix recipe; 3 of 40 answers needed it, none needed a third try.
  • Stock phrases (shahada, bismillah) are allowed; a long run or most of a verse is not.
  • Verify mode was calibrated on 2,856 synthetic verse cases (misquote recall 73% to 99.8% after a bug it exposed) and 1,000 hadith cases.
  • Evals run in parallel (3.7x faster); a rejected-answer trace and per-case token use are stored.
  • Provider-agnostic LLM layer (Anthropic, OpenAI, local) with token counting. Local models run with hidden reasoning off (reasoning_effort=none): 130 output tokens per call instead of about 1,500, with the judge score unchanged.
  • Boundary tests: questions with no sufficient source must decline or carry a limits note (16/16), disputed matters must show positions with a note (6/6), and paraphrased questions must not flip the outcome (5/5).
  • Eval runner reports hidden problems: share of cases routed by the real LLM router, runtime abstentions, first-attempt pass rate, tainted-case warning.
  • Everything beyond the LLM (verify mode, referral, glossary, retrieval) works with no API key.
